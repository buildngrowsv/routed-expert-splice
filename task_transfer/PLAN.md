# Does task training transfer a donor advantage through one frozen feed-forward network?

First screen three executable, single-site code repairs. They cover Python bit-mask updates, Python list aggregation, and SQLite aggregation. Each problem supplies a program prefix and observed examples. Choose one of four single-token legal completions, then run the completed program on twelve concealed cases. The other three patches must be distinguishable on both the examples and the concealed cases. All models receive exactly the same prompt and grammar, with raw model logits deciding the patch. This measures constrained repair. Instances share program templates across splits. Scope conclusions to new inputs from these generators.

Use 128 balanced discovery problems per family. Rank by intact coding donor minus untouched host solve rate, breaking ties alphabetically. Qualify only the highest ranking family with at least a five percentage point lead. Test that family once on 256 independent confirmation problems. Require a positive paired difference with a two-sided exact McNemar p < 0.05. If discovery or confirmation fails, report this screen before designing another one. Never select on the final test. Record all families including failures.

On a qualified family use 1,536 training, 256 validation and 384 new test problems. Keep the six interventions, frozen donor and previously calibrated CPython ridge maps from the upstream surgery. Train only block 28, starting each arm at the original host weights. Use paired order seeds 101, 211 and 307, Adam with FP32 masters, learning rate 0.00002, one epoch, 16 examples per batch, and the lowest validation loss among steps 0, 8, 32, 96. Change supervision to the cross-entropy over legal task patches. Score validation and test through the full model with the actual graft installed. Confirm the intact donor-versus-host comparison again on the final panel.

For every item and seed, release the submitted patch and pass/fail. Define a new solve as a test problem the untouched host failed and the task-trained graft solved. Switch the donor off with that trained host block unchanged. Count disappearing solves, surviving new solves, and gains in the reverse direction. Also count items the intact donor could solve, the frozen graft and task-trained native host both missed, the trained graft solved, and withdrawal erased. Report all three seeds, their overlap, and the number of identities that survive a general/shuffled-donor control. Repeat the frozen-vs-trained withdrawal interaction and crossover from the prior study. Pair comparisons on problem identity, reporting intervals resampling unique instances and paired training orders. Steps, fixture families, models and thresholds are fixed before reading solve results. These are single-token patch tasks with functional oracles, and the donor-off test covers the entire graft including its frozen interfaces.
