# Can a larger model learn around an imported, frozen expert?

Use the published base Qwen2.5-1.5B as the host and the last feed-forward network of the independently pretrained Qwen2.5-Coder-0.5B as the donor. Both process the same token contexts. Learn linear bridges between their different activation spaces on training files only. At the host’s last feed-forward block, a learned per-token soft gate mixes its native output and the imported branch. A small host-side residual adapter trains in all arms. Keep the pretrained trunks and donor fixed. This first test measures functional transfer. A soft gate evaluates both branches and confers no sparse-inference speedup.

Three training arms: host adapter alone, host adapter plus intact graft, and host adapter plus a graft with the donor's up-projection neurons shuffled relative to its gate and down-projection. Fit the same bridges and train the same gate and adapters for both grafts. Evaluate the unmodified host and a forced-off gate as inference controls. Publish routing and intervention effects as well as accuracy.

Use file-disjoint Python source and reStructuredText documentation from a pinned CPython release. Score full-vocabulary next-token negative log likelihood (lower is better) and top-one accuracy. Use 768 training, 128 validation, and 512 test windows per domain, with four targets per window. Balance domains during adaptation, evaluate them separately, and group uncertainty by source file and paired seed. Pretraining overlap with CPython is possible. The experiment evaluates adaptation of existing models, with no claim that CPython was absent from their pretraining.

Run three paired seeds. Select an epoch on the equal-weight mean validation loss across domains from a common four-epoch budget for each arm and seed, including epoch zero. Add two paired seeds only if the intact graft reduces mean validation code loss by at least 0.02 nats/token relative to both trained alternatives while raising documentation loss by at most 0.02 versus the host adapter. Make the screening decision before scoring test data. Positive evidence supports trying hard routing or a deeper insertion next. Otherwise use the controls to distinguish donor-specific transfer from capacity or general adaptation.

## Conditional replacement experiment

The optional route selected epoch zero in every arm, and the first trained epoch drove its average weight nearly to zero. Remove the native last feed-forward block entirely to test trainability around a mandatory graft. Fit input and output bridges on training-only states, then train a rank-32 nonlinear host-side residual corrector for up to eight passes by matching the frozen intact host’s output states. Select among zero, one, two, four and eight passes using validation next-token loss. Run intact and shuffled donor arms for three paired seeds. Compare with complete removal, the unmodified host, the fit-only graft, and removing the fitted donor at inference after training. Reuse the same file split and evaluate fresh non-overlapping windows in the test files. Report paired file-level uncertainty and the share of the knockout loss increase recovered. Compare one actual model with a replaced module against the cached-feature path. This is a recovery experiment; a positive recovery alone does not show that imported expert structure is essential.

## Cost comparison after the forced graft

The intact donor beat the shuffled donor in forced replacement, and the fitted bridges accounted for most of its recovery. As a single cheaper comparator, fit a direct host-input-to-host-FFN-output affine ridge model on the same training states and with the same trace-scaled regularization. Use the same fresh test windows and compare with the fit-only and downstream-adapted intact graft. This comparator has no external weights and no downstream corrector. If it already matches or beats the graft, the graft has not earned its extra cost on this task. Treat this last comparison as exploratory.

## Final donor choice

The fitted intact graft beat a cheaper affine replacement on code loss. Before scaling the host, compare the specialist with one real, same-sized general Qwen2.5-0.5B donor. Both supply the last feed-forward block and receive training-only ridge bridges. Use fit-only grafts because the extra nonlinear corrector had little effect. Hold the host and calibration data fixed. Evaluate a further set of non-overlapping windows from the held-out files; compare next-token loss separately for Python and documentation with file-grouped intervals. The primary contrast is specialist minus general on code. A reduction of 0.02 nats/token or more with the interval below zero would prioritize specialist selection. Otherwise leave larger models and more graft locations for later. This final comparison closes the current screening round.
