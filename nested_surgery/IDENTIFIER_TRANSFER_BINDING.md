# Can a 7B donor carry a letter into the right class in a different 14B program?

We have two results on separate held-out panels. A linear map from the 7B coder reversed 512 of 512 single-definition pairs in the 14B host. A within-host edit reversed 498 of 512 paired reads when the query selected the edited class, versus one for the other class. Combine the two results in one test that changes both the source model and the surrounding program. Run on 256 fresh two-class groups with indices 40000–40255.

For each host file, give the donor a separate one-definition function (indices 50000–50255) with a different identifier stem and different surrounding code. Its two versions carry the same candidate letters as the host file. Translate the donor's declaration-state difference using the exact map fitted in the prior Studio run. Use the resulting vector at either host definition, with the host's two original query variants. The donor sees neither class selector nor host states. Use the same vector and norm at both host sites and both query roles. The two controls are native host inference and a host-only full-token exchange at the selected site.

Use all four native choices to qualify each file. Apply the original binding gate of at least 100 clean groups, at least 50% reversals for the positive control and selected donor edit, at most 10% for the same donor edit at the other class, and a lower paired 95% bound above 25 points on the difference. The new test probes whether a cross-model feature can act at a chosen source in an independent context. It remains a forced two-choice task with known sites and paired letters. Archive both programs and the prior map digest.
