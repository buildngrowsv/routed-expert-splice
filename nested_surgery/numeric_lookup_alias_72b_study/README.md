# Swapping a late alias changed zero complete dictionary lookups in a 72B model

Moving a dictionary key declaration later previously made that site easier to steer. Writing a separate late copy of the original key did not reproduce that effect. At the late alias read, replacing the entire token activation with its counterpart changed **0 of 183** originally correct groups. Replacing it at the earlier source numeral under the same alias syntax changed **111 of 183**. The paired difference was −60.66 percentage points (95% interval −67.76 to −53.55). The late swap preserved the constant-output control in all 183 groups, with 181 preserved in the early swap.

The intervention uses the same 256 matched dictionary groups as the fresh lookup-transfer panel. Each group comprises the direct lookup, reversed dictionary values and a constant-output case, with two otherwise identical input prompts per case. It inserts `selected = mode` after the table and uses `table[selected]` in the return. The two prompts in each pair still differ in only the original key numeral. We swap the full residual activation between paired prompts after the same 17 of 80 layers in Qwen2.5-72B and score the exact next token across the full vocabulary. A switch requires both directions on the direct and reversed cases. [Registered protocol](../NUMERIC_LOOKUP_ALIAS_72B.md) · [Pinned source](../identifier_lookup_alias_72b.py) · [Matched early-key panel](../numeric_lookup_fresh_72b_study/README.md)

The untouched model was correct on all six prompts in 183 groups. At this cut, supplying a counterpart's full state at the alias was insufficient to steer the answer. This test fixes the cut, alias token and surface form. It leaves other readouts, stages and alias syntax open. It shows that the earlier effect from relocating the declaration cannot be reproduced by simple placement of a late read in this setting. ## Reproduce the registered cut

The Studio ran the released BF16 Qwen2.5-72B checkpoint at revision `efba10c8e54e91e0d9570ab5f7b51a958474d4cb`, with no quantization. The process took 354.13 seconds and peaked at 146.54 GB of MLX allocation. The arm64 Apple M5 Ultra has 256 GiB unified memory. Software was macOS build 26B118, Python 3.12.16, MLX 0.32.4, MLX-LM 0.32.2, NumPy 2.5.5 and tokenizers 0.23.3. Run `uv run --with numpy python nested_surgery/numeric_lookup_alias_72b_study/verify.py` from the repo root to reproduce the scoped comparison. The original cut held the intervention depth fixed relative to the earlier positive declaration-relocation test. The paired depth follow-up tests whether the alias can become steerable later with the relocated definition as a concurrent control.
