# Is the apparent coding advantage specific to fill-in-the-middle prompts?

On several executable panels, Qwen2.5-14B chose a colon almost everywhere when asked to repair a missing closing token with fill-in-the-middle markers. Qwen2.5-Coder-7B read the opening bracket much more reliably. The test has so far used one prompt format. On 256 fresh groups at generator indices 80000–80255, score both frozen checkpoints with the original marked prompt, the same markers with an empty suffix, and the raw Python prefix. The prefix ends immediately before the missing closer and is identical across formats. Within each group only the opening bracket changes; one candidate closes it in each case. Restrict comparisons to the same four candidate tokens and require exact decoding of each appended token in every format. [Original donor qualification](large_opener_study/README.md)

The primary endpoint is the raw-prefix difference between the coder and the general host in all-three repair accuracy. Require a net advantage of at least ten percentage points and a positive lower 95% paired bound to keep treating this as a standalone donor opportunity outside the original format. Report colon selections and the change in the donor-host gap across formats. The empty-suffix marked condition distinguishes the impact of removing the suffix from removing the markers, in this specific prompt. No weights change, and these conditions test constrained next-token scoring. Allow about two minutes based on the earlier frozen evaluations.
